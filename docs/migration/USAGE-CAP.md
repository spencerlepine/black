# Usage cap (guardrail + self-recovery; human request 2026-10-12)

Moved out of `MIGRATION-AGENT.md` §5 on 2026-10-13; the summary and the iteration's step 0 are in [§5](../MIGRATION-AGENT.md). The current mode is the `Usage guard` line of `STATE.md`. On a host billed per token (Bedrock, session 4) no cap applies: the `Usage guard` line says so, step 0 is a no-op, and the loop is paused only by the human.

The plan's usage limits are global to the human's account: a rolling 5-hour session limit and a weekly limit. If a limit runs out mid-wave, every in-flight agent dies at once, leaving half-done worktrees and `[~]` lines nobody can explain. So the coordinator watches usage, stops before the limit, leaves the repo clean, and wakes itself up after the reset.

- **Reading usage.** Spawn the `usage-cap-watchdog` agent (`.claude/agents/usage-cap-watchdog.md`; Haiku, ~10 s, foreground, not a worker so it doesn't count toward the cap): `Agent({subagent_type: "usage-cap-watchdog", description: "usage check", prompt: "Report current plan usage. Run exactly: bash $HOME/workplace/black/.claude/scripts/usage-cap.sh"})`. The script path is hard-coded (absolute) in the agent file and the prompt, because agents start in the spirited repo root where `.claude/scripts/` does not exist. It returns one line: `USAGE: <GREEN|ORANGE|RED|UNKNOWN> <worst %> — <each window: %, reset time in Z, time left> [| resume_at <Z> (in …) resume_cron "<M H DoM Mon *>"]`. GREEN <75%, ORANGE 75–89%, RED ≥90% (worst of the windows). `resume_at` is the latest reset among windows at ≥75%, plus a 5-minute buffer, in UTC. `resume_cron` is the same moment in local time, ready for `CronCreate` (which reads cron specs as local time). **Copy `resume_cron` verbatim; never convert time zones yourself.** Never call the usage endpoint yourself and never read the OAuth token.
- **When it runs.** (a) At the start of every iteration (step 0). (b) Every 20 minutes from a session-only recurring cron. Its prompt starts with `USAGE-CHECK`: `CronCreate({cron: "7,27,47 * * * *", recurring: true, prompt: "USAGE-CHECK: run the usage check in docs/migration/USAGE-CAP.md and apply the result. Do not start an iteration or call ScheduleWakeup from this turn unless you are pausing."})`. Step 0 makes sure exactly one such job exists (`CronList`). Recurring jobs auto-expire after 7 days, so recreate it when it's missing. A `USAGE-CHECK` turn only applies the mode below and ends; the loop's pending wakeup still stands.
- **Mode = the latest reading.** Record it in `STATE.md` `Usage guard` (one line, overwritten each time the mode changes). Values: `RUN`, `DRAINING (ORANGE n%) since <Z>`, `PAUSED (<ORANGE|RED> n%) until <resume_at>Z — resume cron <job id>`, or `no cap (per-token billing)`.

| Reading                 | Mode            | What the coordinator does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GREEN                   | **RUN**         | Normal iteration. If `STATE.md` said DRAINING/PAUSED, the limit has recovered: set RUN, note it in `LOG.md`, and continue.                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ORANGE                  | **DRAIN**       | Start nothing new: no worker spawns, no new SEQ item, no retries/escalations. Running workers may finish. Merge each finished one normally (review, commit, rebase, ff-merge, gate + checks on `main`, push), since that's cheap and banks the work. Once no workers are running, **pause**.                                                                                                                                                                                                                                                                                  |
| RED (incl. `LIMIT HIT`) | **WRAP UP NOW** | Start nothing. Merge any worker that has already reported done and whose merge is quick. `TaskStop` every other running worker. Leave its worktree and staged changes alone (never discard) and rewrite its line as `[~] (branch, date) — paused at usage cap; partial work staged in <worktree path>`, so rule 3 hands it back on resume. Then **pause**. If something mid-merge can't finish cleanly (rebase conflict, red gate on `main`), abort it (`git rebase --abort`, or `git revert` + push for a merged range) and put the item back to `[~]`/`[ ]` with a note. `main` must be green and pushed when you stop. |
| UNKNOWN                 | (unchanged)     | Keep the current mode, but spawn no new workers until a reading succeeds. 3 UNKNOWN readings in a row → treat as ORANGE and add a `HUMAN.md` line with the error.                                                                                                                                                                                                                                                                                                                                                                                                              |

- **Pause** (in this order; the goal is that a cold resume can explain everything from the plan files and git alone):
  1. Checkpoint (iteration step 4): every `[~]` line says where its partial work is, `STATE.md` and `LOG.md` are current, commit + `git push origin main`. `git status` on `main` shows nothing staged and no in-progress merge or rebase.
  2. `CronList`, then `CronDelete` the `USAGE-CHECK` job and any older resume job (a paused session must not wake every 20 minutes).
  3. Schedule the resume as a one-shot cron at `resume_cron`: `CronCreate({cron: "<resume_cron, verbatim>", recurring: false, prompt: "<the §0 /loop prompt of MIGRATION-AGENT.md, verbatim>"})`. If the reading had `resume_at unknown`, use 60 minutes from now: `date -d '+60 min' '+%-M %-H %-d %-m *'`.
  4. Set `STATE.md` `Usage guard` to `PAUSED (<ORANGE|RED> <n>%) until <resume_at>Z — resume cron <job id>`, commit + push (one-line message, ` (XX% complete)` as usual).
  5. End the loop: `ScheduleWakeup({stop: true})`. Final message, one line: `PAUSED until <resume_at>Z (<reading>)`.
- **While PAUSED**, any turn other than the resume prompt (a late worker notification, a stray cron) gets one line, `PAUSED until <resume_at>Z`, and no action. Exception: if the human types a message, answer it.
- **Resume.** The one-shot cron re-enters `/loop` with the [§0](../MIGRATION-AGENT.md) prompt. Step 0's usage check decides: GREEN → RUN (reconcile `[~]` per rule 3, then a normal iteration). Still ORANGE/RED (e.g. the weekly window is still high, or other sessions used the reset) → pause again right away with the new `resume_cron`, doing no other work.
