## Method and evidence (what the script uses)

- **Debug source-file strings**: every `*.c` name in the ARM9 string table (0x020A7004..) is pointed to from a literal pool in the
  file that asserts/allocates with it (`Heap_AllocDebug(heap, size, align, "file.c", line)`). pool references = anchors (count in the TSV header of this run: see below).
  A function between two anchors is labelled `exact` (inside an anchor's function..pool span), `bracket` (same file on both sides),
  or `between` (different files: nearest rule, previous file unless the next anchor's function starts within 0x200 bytes, confidence low).
- **ARM9 beyond the last anchor (0x02051C54..)** has no strings: bands (`BANDS` in the script) from callers and library strings
  (gamespy/NWC* = DWC, `[SDK+NINTENDO:BACKUP`, hardware-register pool words, call graph from gflib graphics code).
- **ARC IDs** passed to the verified loaders (`ArcLoadMalloc` 0x020490F4, `ArcLoadData` 0x02048F4C, `ArcLoadMallocEx` 0x0204A1BC,
  0x02048F60, `ArcLoadDataOfs` 0x02048F74, `ArcMemberSize` 0x020490A8) and **message banks** passed to `MsgData_Create` 0x02045B38
  `(type 0, arc 2|3, bank, heap)`; bank previews come from `black-translations/0000/<bank>.txt` (ARC 002).
- **Overlays**: debug strings in the overlay, call targets into main mapped through the same anchors (pseudo-C where a set exists,
  BL decoding otherwise), proc tables (3 consecutive Thumb pointers to function starts), `overlay_load` sites, neighbours.
- Confidence: `high` = debug string inside the span, `med` = bracketed or same-subsystem between anchors / band with corroborating
  strings, `low` = nearest-anchor guess or call-graph only. `unknown` is left unknown.
