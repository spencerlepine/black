## Method (what is computed, what is judged)

1. **Debug-name anchors.** Every field overlay carries its own table of `*.c` names (the arguments of `Heap_AllocDebug`/assert calls) in its data.
   A Thumb `ldr rX,[pc,#imm]` whose pool word points at one marks a function of that source file (68 anchors in 10, 2 in 11, 6 in 18, 6 in 20, 157 in 21).
   Files link in source order, so the anchors, sorted, give one run per file.
2. **Cuts.** Between two runs the cut is the function boundary, between the last function of run A and the first of run B,
   that minimises call edges crossing it (calls to hubs with >= 25 callers ignored). Accurate to a few functions; files without any
   alloc/assert (pure accessor files, `scrcmd.c` bodies) have no anchor and show up as part of a neighbouring run.
3. **Script command table.** The longest run of {null, Thumb code pointer} words in `OVY_10` data is the script command table at
   **0x021705F0**: 624 slots, 614 non-null (index = command id). 569 handlers resolve to indexed functions: 214 in overlay 10, 339 in 21, 8 in 18, 8 in 20;
   command 397 points into overlay 48 (0x021F4650, a gimmick child). Handlers clustered by address (<= 14 fns apart, >= 8 handlers, extended over
   helpers called only from the cluster) are cut out of any non-`scrcmd_*` run as `scrcmd (unanchored)`.
   Command ids interleave across files (ids are assigned in order of addition, not by file), so id ranges do not give file boundaries.
4. **Render score.** Per function: share of callees in main that sit in a render band of `T1-TRIAGE.tsv` (gflib graphics, NNS, MCSS, sound, UI toolkit, SDK, ICA, input),
   MMIO constants (0x04/0x06xxxxxx) in the pseudo-C, then propagated through callees (>= 50% render callees). Only a hint; the class column comes from the label.
5. **ARC loads.** Literal ARC ids / message banks passed to the ROM loaders (`FUN_020490F4`, `02048F4C`, `0204A1BC`, `02048F60`, `02048F74`, `020490A8`, `MsgData_Create 02045B38`) are shown as `arcN` / `msgN`.
6. **Judged by hand:** class, feeding item and role per source file (names, ARC ids, table membership, call neighbourhood). Rows marked UNVERIFIED in the label file are name-based guesses.

Confidence: file *identity* of anchored areas is high (the string is the file's own); *boundaries* are +-a few functions; role labels of rarely-named
files (`event_poke_status`, `event_research_radar`, `el_scoreboard`, `symbol_map`, `fld_btl_inst_tool`) are low.
